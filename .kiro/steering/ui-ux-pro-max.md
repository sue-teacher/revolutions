# UI/UX Pro Max — 디자인 가이드

이 프로젝트의 UI를 만들거나 수정할 때 아래 원칙을 지킨다.
출처: [ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) (라이선스 준수를 위해 핵심 규칙을 재구성함)

## 0. 토큰 우선 (이 프로젝트 규칙)
- 색/간격/반경/그림자는 `src/styles/global.css`의 CSS 변수(`--bg`, `--surface-*`, `--accent`, `--space-*`, `--radius*`, `--shadow*`)만 사용한다. 컴포넌트에 raw hex를 새로 넣지 않는다.
- 간격은 4px 기반 스케일(`--space-1`~`--space-6`)만 사용한다.
- 제목에는 `var(--font-title)`를 쓴다.

## 1. 접근성 (CRITICAL)
- 본문 텍스트 대비 4.5:1 이상, 큰 텍스트·비텍스트 UI는 3:1 이상.
- 모든 상호작용 요소에 보이는 포커스 링(`:focus-visible`에 `--ring`)을 둔다.
- 아이콘 전용 버튼에는 `aria-label`을 준다. 장식용 이모지/아이콘은 접근성 트리에서 숨긴다(`aria-hidden`).
- 정보를 색만으로 전달하지 않는다(아이콘/텍스트 병행).
- 제목은 h1→h6 순서를 건너뛰지 않는다.
- `prefers-reduced-motion`을 존중한다(이미 global.css에 전역 처리됨).
- 웹 포인터 타깃은 최소 24×24 CSS px, 터치 주 타깃은 44px 이상.

## 2. 스타일 선택 (HIGH)
- 구조적 아이콘은 이모지 대신 SVG를 쓴다. (이 프로젝트는 학습용·캐주얼 톤이라 장식 이모지는 허용하되, 핵심 컨트롤은 접근성 이름을 반드시 부여)
- 모든 페이지에서 같은 스타일·같은 아이콘 언어·같은 엘리베이션 스케일을 쓴다.
- 화면마다 primary CTA는 하나만. 보조 액션은 시각적으로 약하게.
- hover/pressed/disabled 상태를 서로 명확히 구분한다.

## 3. 레이아웃 & 반응형 (HIGH)
- 모바일 우선. 브레이크포인트는 기존(560 / 760)과 일관되게.
- 모바일 본문 16px 이상, 가로 스크롤 없음.
- 데스크톱 콘텐츠 최대 폭 일관 유지(`.app-shell` max-width).
- 고정(sticky) 요소 아래 콘텐츠가 가려지지 않도록 여백 확보.
- 시각적 위계는 크기·간격·대비로 세운다(색만으로 X).

## 4. 타이포 & 색 (MEDIUM)
- 본문 line-height 1.5~1.75, 한 줄 길이는 과하게 길지 않게.
- 타입 스케일을 일관되게. 굵기로 위계 보강.
- 숫자가 열로 정렬되는 곳(점수/연도/타이머)은 tabular 숫자 고려.
- 의미색(정답 초록, 오답 빨강)은 아이콘/텍스트와 함께.

## 5. 애니메이션 (MEDIUM)
- `transform`/`opacity`만 애니메이션(레이아웃 리플로우 유발 금지).
- 화면당 1~2개 핵심 요소만 움직인다.
- 들어올 때 감속, 나갈 때 가속. 종료 애니메이션은 진입의 60~70% 길이.
- 모든 모션은 `prefers-reduced-motion`에서 사실상 비활성화.

## 6. 폼 & 피드백 (MEDIUM)
- 라벨은 placeholder가 아니라 보이는 라벨로.
- 에러는 해당 필드 근처에 구체적으로, 복구 경로를 포함.
- 제출 시 로딩→성공/에러 상태 표시. 비동기 중 버튼 비활성화.
- 파괴적 동작(초기화/삭제)은 확인 다이얼로그 + danger 색 + 다른 액션과 분리.

## 납품 전 체크
- 375px(소형폰)·가로모드에서 확인
- 다크 톤 대비 재확인(이 앱은 다크 테마)
- 모든 터치 타깃·포커스 링 확인
- 색만으로 의미 전달하는 곳 없는지 확인
